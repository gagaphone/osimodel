What Is the OSI Model?

The Open Systems Interconnection (OSI) model is a conceptual framework developed by the International Organization for Standardization (ISO). Published in the 1980s, it organizes network communication into seven layers, each with a distinct role.

As data travels through the model, each layer provides services to the layer above it and uses services from the layer below it. This layered approach helps explain network communication, design, and troubleshooting.

The OSI model is a reference model rather than a protocol suite. Real-world internet communication is primarily based on the TCP/IP model, while the OSI model remains a useful framework for learning and diagnosing network problems.

Why does the OSI model matter?

  • Interoperability: Helps explain how systems from different vendors communicate using common standards.
  • Troubleshooting: Helps narrow a fault down to a likely layer, such as a cable, VLAN, route, or application.
  • Protocol design: Provides a structured way to understand networking functions.
  • Learning: Gives networking students and certification candidates a common reference framework.

Layer-by-Layer Deep Dive

Layer 1 — Physical

The Physical Layer transmits raw binary data across a physical medium. It deals with signals, timing, connectors, physical topology, and the characteristics of cables or radio.

PDU
Bit (1s and 0s)
Responsibilities
Signal encoding, bit timing, physical media, duplex settings
Examples
Ethernet copper, fibre optic cable, Wi-Fi radio, DSL, coaxial cable
Devices
Cables, connectors, hubs, repeaters, transceivers
Typical fault
Damaged cable, disconnected port, bad transceiver, incorrect cable distance
Real-world example: A user has no network connection. Check that the cable is connected and the switch-port link light is on, then test with a known-good cable.
Layer 2 — Data Link

The Data Link Layer organizes bits into frames and supports delivery across a local network link. Ethernet and Wi-Fi use link-layer addressing and media-access mechanisms.

PDU
Frame
Sub-layers
LLC (Logical Link Control) and MAC (Media Access Control)
Addressing
MAC addresses, commonly represented as six hexadecimal octets
Protocols
Ethernet, Wi-Fi, PPP, VLAN tagging, STP, LACP
Devices
Switches, bridges, wireless access points, network adapters
Typical fault
VLAN mismatch, switching loop, MAC-learning issue, frame errors
Real-world example: A switch learns source MAC addresses and uses its MAC address table to forward frames toward the correct port.
Layer 3 — Network

The Network Layer provides logical addressing and routes packets between different IP networks. Routers inspect destination IP addresses and consult their routing tables.

PDU
Packet
Addressing
IPv4 (32-bit) and IPv6 (128-bit)
Protocols
IP, ICMP, OSPF, EIGRP, RIP, BGP
Devices
Routers, Layer 3 switches, packet-filtering firewalls
Typical fault
Missing route, wrong subnet mask, incorrect default gateway
Real-world example: A host sends a packet to a server on another network. A router checks its routing table and forwards the packet toward the destination network.
Layer 4 — Transport

The Transport Layer supports communication between application processes on different hosts. Transport ports identify the source and destination application endpoints.

PDU
TCP segment or UDP datagram
Protocols
TCP, UDP, SCTP
TCP
Connection-oriented transport with sequencing, acknowledgements, retransmission, and flow control
UDP
Connectionless transport with lower overhead and no built-in retransmission
Typical fault
Blocked port, failed TCP handshake, wrong port configuration
TCP vs. UDP: A conventional web connection using HTTP/1.1 or HTTP/2 typically uses TCP. Many real-time applications use UDP where reducing delay is important. HTTP/3 uses QUIC over UDP.
Layer 5 — Session

The Session Layer describes functions for establishing, maintaining, coordinating, and terminating conversations between applications. Session functions may include dialogue control and checkpoints.

PDU
Data
Examples
NetBIOS session services, RPC, SMB, NFS, and session-related functions in applications
Functions
Session establishment, maintenance, graceful termination, checkpoints
Typical fault
Session timeout, authentication failure, session limits
Real-world note: In modern TCP/IP systems, session functionality is often implemented by application protocols and software rather than a separate visible layer.
Layer 6 — Presentation

The Presentation Layer describes how data is represented so that different systems can interpret it consistently. Related functions include encoding, serialization, encryption, and compression.

PDU
Data
Encoding
ASCII, Unicode, EBCDIC
Data formats
JSON, XML, JPEG, GIF, MPEG, MP3
Security
TLS provides encryption in modern network stacks; its placement in OSI is a conceptual simplification
Typical fault
Encoding mismatch, certificate problem, incompatible data format
Real-world example: Applications encode text as UTF-8 and may compress content before transmitting it. Secure connections use TLS to protect data in transit.
Layer 7 — Application

The Application Layer provides network protocols and services used by software such as browsers, mail clients, file-transfer tools, and management applications. It describes the protocol interface, not the application program itself.

PDU
Data
Web
HTTP and HTTPS
Email
SMTP, IMAP, POP3
Other protocols
FTP, SFTP, DNS, DHCP, SNMP, SSH, Telnet
Typical fault
Incorrect URL, application configuration, unavailable service, DNS lookup issue
Real-world example: A browser requests a page using HTTP or HTTPS. DNS may first resolve the domain name to an IP address so the browser can connect to the destination.

HOW DATA MOVES

Encapsulation and Decapsulation

Encapsulation occurs as data moves down the sender's stack: each layer adds information needed for delivery. Decapsulation occurs at the receiver, where the appropriate headers and trailers are examined and removed.

Sender: Encapsulation ↓

Layer 7 · Application HTTP data
Layer 4 · Transport TCP header | HTTP data
Layer 3 · Network IP header | TCP segment
Layer 2 · Data Link Ethernet header | IP packet | FCS
Layer 1 · Physical Bits: 10101001 01101101 ...
Across the physical medium ⇄ Electrical, optical, or radio signals

Receiver: Decapsulation ↑

Layer 1 · Physical Signals become bits
Layer 2 · Data Link Check frame and remove link header
Layer 3 · Network Inspect IP packet and destination
Layer 4 · Transport Process transport ports and data
Layer 7 · Application Deliver HTTP data to the service

Physical travel vs. logical communication

Bits physically travel over the medium. Other layers communicate logically with their corresponding peer layers through protocol rules and headers. This is why a Layer 4 protocol can define end-to-end behavior even though the transmitted bits pass through Layer 1.

RELATED NETWORK MODEL

OSI Model vs. TCP/IP Model

The TCP/IP model describes the protocol architecture commonly used for internet communication. In its four-layer version, several OSI layers are grouped together.

OSI Layer TCP/IP Four-Layer Model Examples
7 — Application Application HTTP, HTTPS, DNS, DHCP, SMTP, SSH
6 — Presentation Application Data formats, encoding, encryption functions
5 — Session Application Session and dialogue functions
4 — Transport Transport TCP, UDP
3 — Network Internet IPv4, IPv6, ICMP, routing
2 — Data Link Network Access / Link Ethernet, Wi-Fi, PPP, VLAN
1 — Physical Network Access / Link Cables, optical signals, radio signals

Key difference

The four-layer TCP/IP model groups the OSI Session, Presentation, and Application functions into its Application layer, and groups the Physical and Data Link functions into Network Access. Five-layer TCP/IP diagrams often separate the link and physical functions for teaching.

PRACTICAL NETWORKING

Troubleshooting by OSI Layer

The OSI model helps organize troubleshooting. Start at the physical connection and work upward, or use symptoms to begin with the most likely layer.

Layer Common Problems Diagnostic Ideas and Commands
L1 — Physical Unplugged or damaged cable, failed transceiver, no link Check link LEDs, inspect cables, test with a known-good cable
L2 — Data Link VLAN mismatch, switching loop, frame errors Inspect VLAN configuration, MAC address table, spanning tree and interface errors
L3 — Network Missing route, incorrect subnet mask, wrong gateway ping, traceroute, route-table inspection
L4 — Transport Blocked port, TCP handshake failure, incorrect port Test TCP connectivity, inspect firewall rules, capture packets
L5 — Session Session timeout, session limit, authentication failure Review application logs and session-management settings
L6 — Presentation Certificate issue, encoding mismatch, data-format error Review browser security warnings, TLS configuration and application logs
L7 — Application Unavailable service, wrong URL, DNS or application error Try nslookup, dig, curl -v or browser developer tools

Example: A user cannot open a secure website

  1. Check physical connectivity and the local network.
  2. Check whether the destination can be reached by IP address.
  3. Test whether the TCP service port is reachable.
  4. If a certificate warning appears, investigate TLS and certificate configuration.
  5. If the server responds with an HTTP error, investigate the URL, server, and application configuration.

These checks narrow the possibilities but do not prove that every lower layer is fault-free. Interpret results in context.

Important Note About Layer Mappings

The OSI model is a conceptual reference, and real-world networking implementations do not always align perfectly with a single layer. Some protocols and technologies span several layers, while the Session and Presentation functions are often handled by application software and protocols in modern TCP/IP networks.
